# 0.6.0

Candidate additive managed-execution contracts. The first implementation stage supports
reviewed non-bootstrap GET operations with service-owned OAuth credentials, an explicit
deployment/tenant/package execution allowlist, consented scope checks, pinned provider
destinations, inventory-bound resources and final transactional authority checks.

Execution is disabled by default. Enrollment, package approval and OAuth consent do not
create execution policies. A deployment signature authenticates the caller and exact
operation; it does not independently prove human consent or a Core business/agent grant.

Adds durable resumable-media claims, encrypted service-owned sessions/results, exact signed
bounded chunks, probe-based uncertainty recovery, idempotent initiation, local cancellation,
expiration and transactional authority/lease checks. The service store upgrade is additive
and explicit. Core integration requires this package plus the separately reviewed Core change.

The current YouTube 0.2.1 upload mapping lacks the required response resource pointer and
remains rejected. A new reviewed connector release and explicit deployment execution policy
are required before use. Synthetic tests do not establish real-provider acceptance, processing
or visibility. No live migration, deployment, grant, upload or package publication is performed
by source verification. Human approval and complete attachment checksum/provenance remain
Core responsibilities; signatures independently establish deployment identity and exact bytes.
